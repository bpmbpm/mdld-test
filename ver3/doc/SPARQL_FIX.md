# Почему SPARQL-запросы 04–07 в ver2 возвращали пустой результат

## Корневая причина
В заметках ver2 объявлен только префикс `ex`:
```
[ex] <tag:example.org,2026:>
```
Префикс `schema` в `mdld-parse@1.0.8` **не предопределён**. Разбор `ver2/notes/note1.md` выводит:
```
Undefined prefix "schema" in IRI "schema:Person" - treating as literal
```
и создаёт IRI `<schema:Person>`, `<schema:name>` вместо `<http://schema.org/Person>`. Запрос
`PREFIX schema: <http://schema.org/> … ?p a schema:Person` поэтому ничего не находит (01 работал, т.к. без фильтров).

## Дополнительные ошибки разметки ver2
1. `- [ул. Ленина, д. 10] {schema:streetAddress}` — в элементе списка скобки попадали в литерал
   (`"[ул. Ленина, д. 10]"`), а свойство вешалось на персону, а не на адрес (`{+…}` в заголовке не меняет субъект).
2. В note2 заголовки `## От кого {+ex:alice … schema:name}` давали Алисе имя «От кого», расстоянию — имена «Алиса», «Боб».
3. Хобби получали имя по тексту в предложении («фотографией»), а не отдельную сущность.

## Исправление (ver3/notes)
* в каждую заметку добавлено `[schema] <http://schema.org/>`;
* адрес и увлечения — отдельные сущности через `{=…}` (заголовки), связь — через `{+… ?schema:…}`;
* литералы — без маркеров списка; `schema:value` типизирован `^^xsd:integer`.

## Запросы (ver3/SPARQL)
* 02, 03 — в данных нет `schema:CreativeWork`/`schema:author`; заменены на «все именованные сущности» и «количество по типам»;
* 04 — плюс город (путь `schema:address/schema:addressLocality`);
* 05, 06, 07 — выводят имена, а не только IRI.

| Запрос | ver2 | ver3 |
|--------|------|------|
| 04-persons | 0 | 2 (Алиса/Москва, Боб/Химки) |
| 05-hobbies | 0 | 4 |
| 06-worksfor | 0 | 2 |
| 07-distance | 0 | 1 (Алиса → Боб, 11 km) |

Проверяется тестом `tests/sparql.test.js` (в т.ч. воспроизведение пустых результатов на данных ver2).
